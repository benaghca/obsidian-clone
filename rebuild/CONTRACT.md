# Rebuild contract (Tauri 2 + TypeScript + CodeMirror 6)

The new app lives entirely in `rebuild/app/` (a fresh Tauri 2 project). The old Cinder code at the repo root is reference only; do not edit it.

Goal: get as close as possible to how Obsidian looks, feels, and responds. `rebuild/OBSIDIAN_FEEL_SPEC.md` is the target. Notes are plain `.md` files in a vault folder (Obsidian vault format).

## Ownership
- Front end (Claude): `rebuild/app/src/`, `rebuild/app/index.html`, `rebuild/app/package.json`, `rebuild/app/vite.config.ts`, styles. Vite + TypeScript + CodeMirror 6. No React or other UI framework around the editor; plain TS + DOM for chrome.
- Backend (Grok): `rebuild/app/src-tauri/` (Rust, Tauri 2).
- Neither side edits the other's files. If the contract needs to change, edit this file and say so in the commit message.

## Tauri commands (backend implements, front end calls via `invoke`)
Read commands run off the main thread; replies to separate calls may arrive in any order.
- `open_vault(path: String) -> VaultInfo { path, name }` — remembers last vault.
- `create_vault(path: String) -> VaultInfo { path, name }` — creates one new empty vault folder and opens it (same remember and watch as `open_vault`). The parent must already be a folder. An empty path, a missing parent, and a path that already exists are refused, so nothing is overwritten. Added in round 27.
- `last_vault() -> Option<VaultInfo>`
- `list_files() -> Vec<FileEntry { path (vault-relative, forward slashes), name (no .md), is_dir, mtime_ms, ctime_ms, size }>` — recursive, skips `.obsidian`, `.git`, `.trash`, `.grove`, `.cinder`. `ctime_ms` is when the file was created (its modified time where the file system doesn't record that; 0 for folders), for the "Created time" sort orders; added in round 15. `create_note` and `create_folder` return the same entry.
- `read_note(path: String) -> String`
- `read_file_bytes(path: String) -> bytes` — an image file's raw bytes (a `tauri::ipc::Response`, so the page gets an `ArrayBuffer`), for `![[embeds]]`. The same path checks as `read_note` (vault-relative, no `..`, no symlink out of the vault, nothing in `.grove/`, `.obsidian/`, `.cinder/` or the other hidden folders), only `png`, `jpg`, `jpeg`, `gif`, `webp`, `svg`, `bmp`, `avif` (any case), at most 20 MB. Permission `allow-read-file-bytes` in the default capability. The front end shows the bytes through a `blob:` URL it revokes when no embed shows it (the CSP already allows `img-src blob:`); Tauri's asset protocol stays off. Added in round 12.
- `write_note(path: String, content: String) -> ()` — atomic write (temp file + rename). Front end debounces saves ~300ms. Other windows (a note's own window) get a `vault-changed` `modify` for it; the window that saved does not. Changed in round 9.
- `set_property(path: String, edit: PropertyEdit, dry_run?: bool) -> EditResult` — K2, asynchronous/off GTK, `allow-set-property`. The vault mutex covers a fresh UTF-8 read (existing regular `.md` note, any case, ≤16 MB), formatting/validation, property-line CAS, final metadata check, atomic write and index update. Existing file symlinks and paths resolving into ignored folders are refused. `PropertyEdit = {key, expect: string|null, to: {type: PropertyType, value: string|boolean|string[]} | {lines: string} | null}`. `expect` and exact undo `lines` are property source lines with CR stripped and LF separators; null means absent/removal. Keys match case-insensitively, while written spelling is retained. A typed empty target on an absent key is unchanged; an exact-lines undo can restore an empty key. Unsupported/commented target properties and unsafe frontmatter are refused. Other properties and the body are preserved byte-for-byte; scalar quotes, flow/block lists, item indent and existing line endings are retained, with new endings taken from the opening fence. Three metadata retries protect concurrent external writes (size, full mtime, Unix device/inode/ctime); the remaining external stat-to-rename race is not a cross-process lock.
  - Success: `{status: "done"|"unchanged", before: string|null, after: string|null, props: NoteProperties, mtime_ms}`; conflict: `{status: "conflict", current: string|null}`; refusal: `{status: "refused", reason}`. Disk errors/no open vault are command errors. Already-equal target lines are unchanged even if `expect` is older. The result contains no full note text.
  - `dry_run` (default false) performs the same read/validation/CAS/stat checks and returns prospective metadata with the current file mtime, without writing, touching the index, marking own writes or emitting events. A real done result updates properties/tags/links before returning, suppresses watcher echo, and emits `vault-changed` modify only to other windows. The caller calls `vault.written` to reconcile its own page. Unchanged/conflict/refused emit nothing.
  - Loaded editors must use the pure TS twin `editor/propertyEdit.ts` and apply its optional UTF-16 `change` in one editor transaction, not call this command. Its mtime placeholder is 0; the filesystem/mock caller supplies the authoritative mtime. The shared `fixtures/parity/property-edits.json` is checked by both implementations. K2 edits both Rust and TS under the approved Kanban split.
  - All atomic writers now copy the old mode and sync the file before rename, then sync the parent directory on Unix (std has no portable directory-fsync operation on other targets). Startup sweeps abandoned `*.grove-tmp` regular files without following symlinks, skips `.obsidian`/`.git`/`.trash`/`.cinder` (it still sweeps `.grove`, where settings saves leave temps), and preserves the current process's temps and, on Linux, temps belonging to any live PID. Hard links, ownership and extended attributes are not preserved by replacement; see KANBAN_PLAN R6.
- `read_clipboard_image() -> null | bytes` — the system clipboard's image, for a paste WebKitGTK would otherwise hand the page as an empty event. Async, off the GTK thread. No vault needs to be open. Permission `allow-read-clipboard-image`. Linux only, through `std::process` and nothing else: when `WAYLAND_DISPLAY` is set, `wl-paste --list-types` then `wl-paste --no-newline --type <mime>`; otherwise `xclip -selection clipboard -t TARGETS -o` then `xclip -selection clipboard -o -t <mime>`. The mime is the first of `image/png`, `image/jpeg`, `image/webp`, `image/gif`, `image/bmp` whose line matches exactly (PNG wins when both are offered). A missing tool is a command error, `install wl-clipboard to paste images` or `install xclip to paste images`. Any other failure to start the tool is `{program}: {error}`. No image, an empty read, or a clipboard with no image type is JSON `null` (not an error). An image is a raw body (`ArrayBuffer`): the mime, one `\n` (`0x0A`), then the image bytes unchanged. Split on the first newline only; the bytes may contain newlines. The extension is the mime subtype, with `jpeg` saved as `jpg`. Over 20 MB is `too large to paste` (the read stops at the cap and does not return the bytes). A type list over 64 KB is `clipboard type list is too large`. On macOS and Windows this returns `null`; those webviews hand the image to the page. Added in I1. The page calls it when a paste carries neither a file nor text, then saves and embeds the image the same way as a pasted file. Pasting an image on a canvas adds one file card at the pointer, in one undo step. The browser mock returns `null` until `setMockClipboardImage` arms a packed body; it does not read the system clipboard.
- `write_file_bytes -> FileEntry` — a new attachment (a pasted image or a dropped file). Async, off the GTK thread. The body is the raw file bytes, a `Uint8Array` or `ArrayBuffer` passed as the whole `invoke` argument (`application/octet-stream`), not a JSON array of numbers. The vault-relative path is the `x-grove-path` request header: percent-encoded UTF-8, `/` and `A-Za-z0-9-._~` left as themselves, every other byte as uppercase `%HH` (a space is `%20`, not `+`). The same path checks as `write_note` (vault-relative, no `..`, no symlink out of the vault, nothing in `.grove/`, `.obsidian/`, `.cinder/`, `.git` or `.trash`). Fails if the header is missing (`missing x-grove-path`) or does not decode (`invalid x-grove-path`), if the body is JSON (`write_file_bytes expects a raw body, not JSON`), if anything already exists at `path` (the caller picks a free name), or if `bytes` is over 20 MB. Any extension, including none; empty is allowed. Parents are created. Other windows get a `vault-changed` `create`; the window that saved does not. Permission `allow-write-file-bytes`. Changed in I1: round 27 took `bytes` as a JSON array of numbers on the main thread. The front end calls it like this:

  ```ts
  function encodeGrovePath(path: string): string {
    const hex = "0123456789ABCDEF";
    let out = "";
    for (const byte of new TextEncoder().encode(path)) {
      if ((byte >= 0x41 && byte <= 0x5a) || (byte >= 0x61 && byte <= 0x7a) || (byte >= 0x30 && byte <= 0x39) || byte === 0x2d || byte === 0x2e || byte === 0x5f || byte === 0x7e || byte === 0x2f) out += String.fromCharCode(byte);
      else out += "%" + hex[byte >> 4] + hex[byte & 0xf];
    }
    return out;
  }
  await invoke("write_file_bytes", bytes, { headers: { "x-grove-path": encodeGrovePath(path) } });
  ```

  `src/api.ts` `writeFileBytes` uses that call in the desktop app. The browser mock still takes `{ path, bytes: number[] }`: the page has no raw IPC headers there. I2 left that shape in place and added `read_clipboard_image` beside it.
- `create_note(path: String, content: String) -> FileEntry`
- `create_folder(path: String) -> FileEntry` — creates an empty folder (the file explorer's "New folder"); errors if anything already exists at `path`. Added in round 4.
- `rename_path(from: String, to: String) -> ()` — and returns nothing; front end updates links itself later.
- `delete_path(path: String, permanent?: bool) -> ()` — move to `.trash/` in the vault; with `permanent: true` (the "Deleted files: Permanently delete" setting) remove it instead. `permanent` is optional and defaults to false. Changed in round 6.
- `read_config(name: String) -> Option<String>` — a settings file from the vault's config folder `.grove/` (Grove's `.obsidian/`), or `None` if it doesn't exist. Added in round 6.
- `write_config(name: String, content: String) -> ()` — write a settings file into `.grove/` (created if missing), atomically (temp file + rename). `content` must parse as JSON. Added in round 6.
  - For both: `name` must be a plain lower-case file name ending in `.json` (`[a-z0-9-]+\.json`, at most 64 characters before the extension), so nothing outside `.grove/` can be named; a `.grove` that leads outside the vault (a symlink) is refused; files over 1 MB are refused.
  - `.grove/` is hidden like `.obsidian/`: never listed, searched, indexed or reported by the watcher, and the note commands refuse paths inside it.
- `read_foreign_config(source: String, name: String) -> Option<String>` — one allowlisted settings file from Cinder or Obsidian, or `None` if it does not exist. Read-only: it never creates or writes the file. Async, off the main thread, permission `allow-read-foreign-config`. Added for the Cinder settings import (M0a).
  - The allowlist is an exact match, and every other source/name pair is refused:
    - `cinder` + `settings.json` reads `.cinder/settings.json`
    - `obsidian` + `daily-notes.json` reads `.obsidian/daily-notes.json`
    - `obsidian` + `templates.json` reads `.obsidian/templates.json`
    - `obsidian` + `app.json` reads `.obsidian/app.json`
  - Same 1 MB cap as `read_config`. A `.cinder` or `.obsidian` folder, or the file itself, that leads outside the vault (a symlink) is refused. The bytes are returned as text and are not required to be JSON.
  - `.cinder/` is hidden like `.obsidian/`, `.git/`, `.trash/` and `.grove/`: never listed, searched, indexed, watched, or openable through the note and path commands. This command is the only reader for the one allowlisted file inside it.
  - Caller (M0b): `src/settings/importSettings.ts`, once, in the main window, on an open where `read_config` found none of Grove's settings files in `.grove/`. It reads all four in parallel; Cinder's file wins when it parses, and any read error or bad JSON stops the import with nothing written (`src/settings/foreign.ts`). What is imported is saved with `write_config` to `daily-notes.json`, `templates.json` and `app.json`. The browser mock serves these files from `localStorage` keys `grove.mock.foreign:<source>/<name>` and never writes them.
- `search(query: String, limit: u32) -> Vec<SearchHit { path, line, text }>` — case-insensitive; every word must be on the same line. File-name matches use `line: 0` and come first. Other hits are round-robin across files so one note cannot fill `limit`.
- `search_notes(query: String, match_case: bool) -> SearchNote[] { path, count }` — all matching notes (`.md` in any case) in vault path order; TS filters excluded/missing files and sorts with its locale-aware comparator. Count every highlight occurrence in shown lines, overlapping ones once. Saved text only; the search view flushes pending saves first, keeps one request in flight, and drops stale replies. Nothing to search for (including nesting beyond 64 levels) returns `[]`; no query is an error. The only command error is no vault open. Payload uses `{path,count}` objects, about 60 B per matching note (about 120 KB at 2,000, 0.3 MB at 5,000). Async, index-only, `allow-search-notes`. Added in migration step 4, one owner editing both sides and this contract.
- `search_lines(query: String, match_case: bool, paths: string[], limit: u32) -> { [path]: { line, text }[] }` — independently re-evaluate requested notes and return at most `limit` shown lines per note, in line order. Positive text terms, matching same-line groups, and matched properties provide lines; `file:`/`path:` terms provide none. Missing/nonmatching/non-note paths and notes with no shown lines are omitted. The view reads only drawn batches (first five lines per note); an omitted path still draws a file row. Async, index-only, `allow-search-lines`.
- `search_match(queries: string[]) -> string[][]` — each query's matching files (notes and attachments, never folders) in vault path order, Match case off. Nothing to search for returns `[]` for that element; the graph treats null queries as everything and never sends them. The graph flushes pending saves, batches backend queries in one call, and retains its last answer until a vault change; file/path-only queries still evaluate in TS. Async, index-only, `allow-search-match`. Matching/shown-line/count rules are the TS reference (`shell/searchQuery.ts`, `searchVault.ts`) ported in `index/query.rs` and `index/search.rs`, checked by the shared query/search corpus. The old `search` stays for unlinked mentions.
- `link_index() -> LinkIndex { outgoing: { [path]: string[] }, markdown: { [path]: string[] }, unresolved: { [path]: string[] } }` — `[[wikilinks]]` resolved by note name, case-insensitive.
  - `outgoing` holds wikilinks (and `![[embeds]]`) only. Linked mentions are fetched separately with `backlinks` (migration step 2).
  - `markdown` (added in round 7, for the graph view): per note, the resolved targets of its `[text](path)` and `![alt](path)` links to files in the vault. URLs (anything with a scheme) and `#heading` anchors are not links here; the path is percent-decoded and resolved like a wikilink path (from the note's folder, then the vault). Notes with none are omitted.
  - `unresolved` (added in round 7): per note, the link targets (wikilinks and markdown links) that match no file, as written without heading, alias or a markdown link's `.md`, deduplicated case-insensitively. Notes with none are omitted.
  - Links in fenced or inline code are skipped in all three.
- `backlinks(paths: string[]) -> { [path]: { from, line, text }[] }` — linked mentions resolving to the requested vault-relative targets only, from both wikilinks/embeds and Markdown links. Each occurrence is counted, including multiple links on one line; `line` is 1-based and `text` is the full source line. Targets without mentions (including missing paths) are omitted; an empty request returns `{}`. Uses the same resolution and code-skipping rules as `link_index`, runs off the main thread, and requires `allow-backlinks`. For the status bar and the backlinks pane. Added in migration step 2.
- `link_sources(paths: string[]) -> string[]` — every note that might link to one of `paths`, for a rename. That is every note whose links resolve to one of those paths, plus every note whose text contains one of their names in any link spelling Grove rewrites: the bare name, spaces as `%20`, `encodeDest` (percent-encoded spaces and parentheses), and parentheses escaped with a backslash. Sorted, duplicates removed. An empty request returns `[]`. There is no note cap and no hit cap. A spelling has to appear as itself (any case); separate words on the same line do not count. Runs off the main thread and requires `allow-link-sources`. Fetch it **before** `rename_path` and pass that list to link rewriting; old-name links may no longer resolve afterward. The text rewrite stays in TypeScript. Added in migration step 5.

- `frontmatter(paths?: string[]) -> { [path]: string }` — each note's frontmatter block, from its first line (`---`) to the closing `---` (both included), lines joined with `\n`; for `paths` only when given, every note otherwise. Notes without frontmatter (or with more than 2,000 lines of it) are left out. Read from the index, never from disk. For the properties index (All properties view, property suggestions, `[property]` search). Added in round 10.
- `properties(paths?: string[]) -> { [path]: { props: Property[], lines: string[] } }` — saved-note properties parsed once when indexing; `paths` restricts targets, omitted means all notes (`.md` in any case). Omit notes without frontmatter, over the 2,000-line scan cap, or whose YAML must remain source. Empty readable blocks return `props: []`. Each property has `{ key, type, value, line, count }`: numbers/dates/unknowns remain strings, checkboxes are booleans, lists/tags/aliases are string arrays; `line` is zero-based within the body lines and `count` covers its complete source extent. `lines` contains the body without fences or CRLF carriage returns. Matches `splitFrontmatter` + `readProperties` (including trimmed opening fences/BOM and conservative unknown types); the editor still parses unsaved text locally. Async, index-only, permission `allow-properties`. Added in step 3 with one owner editing both Rust and TypeScript, per the migration plan.
- `tags(paths?: string[]) -> { [path]: string[] }` — each note's tags without the `#`, in order, repeats kept: its frontmatter `tags:`/`tag:` values, then the body's `#tags` outside fenced and inline code. The rules are `tagsInText`'s (`src/shell/linksTags.ts`), ported in `index/tags.rs`; `fixtures/parity/tags.json` holds both to the same cases. For `paths` only when given, every note otherwise. Notes without tags are left out. Read from the index, never from disk. For the Tags view, `tag:` search, the graph and Bases (`vaultTags.ts`). Added in plan step 1 (both sides edited by one owner, as `RUST_MIGRATION_PLAN.md` §2 proposes).
- `open_note_window(note: String) -> ()` — "Open in new window": a window of its own (label `note-<n>`, the main window's settings, navigation guard and capability) on `index.html?note=<note>`. `note` is the vault path, percent-encoded in full (only `A-Za-z0-9%-._~`); anything else is refused. Added in round 9.
- `allow_frame_origin(origin: String) -> ()` — register one http(s) origin so an embedded frame may navigate there. `origin` is origin form only: `http://host[:port]` or `https://host[:port]`, with no user, path, query, or fragment. The stored form lowercases the host and drops a default port (`:80` or `:443`). `file:`, `javascript:`, `data:`, a path, or any other shape is refused. The main frame still cannot navigate there. Registering an origin does not grant that origin IPC. Async, off the main thread, permission `allow-allow-frame-origin`. Added for embedded web pages (W1). The page calls it just before creating the frame: a web embed in a note (`src/editor/webEmbed.ts`, W2) registers the page's origin, plus its `www.` twin and https for a domain address without a port, so the site's own redirects load.

## Events (backend emits)
- `vault-changed` payload `{ kind: "create"|"modify"|"remove"|"rename", paths: string[] }` from a debounced (~100ms) file watcher. Ignore changes caused by our own `write_note` or `write_file_bytes` within 500ms.

## Feel/performance bar
- Typing never lags on a 5,000+ line note; note switching feels instant (<50ms); popups open instantly.
- All commands return in under 50ms for a 1,000-note vault (search may take up to 150ms).
