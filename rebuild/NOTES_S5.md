## What changed

`link_sources(paths) -> string[]` is a new `#[tauri::command(async)]`. It returns every note whose indexed links resolve to one of `paths`, plus every note whose text contains one of their names in a spelling a rename already looks for. There is no 20-note cap and no 500-hit cap. `relocate` calls it before `rename_path`. `rewriteLinks` stays in TypeScript and still edits unsaved editor text.

Search is untouched: `searchQuery.ts`, `searchFacts.ts`, `searchView.ts`, `index/query.rs`, and `index/search.rs` were not edited. The status bar and the backlinks pane still use `backlinks`.

## Decisions

The five spellings are the queries `links/update.ts` already sent to search: the bare note name (`noteName` / basename without `.md`), spaces written as `%20`, parentheses escaped with a backslash, and both `encodeDest` forms from `links/internal.ts`. They are Grove's existing rename queries. This step does not claim a new Obsidian rule, and no public doc was fetched.

A spelling matches as a contiguous case-insensitive substring of a line. It does not match as separate words. "my favorite note" does not count as a mention of "My Note". The old search required every word on the same line, so that line used to count. Real link spellings are contiguous, and `rewriteLinks` only edits a real link, so the extra word-split hits were not rewritten into new destinations. CONTRACT.md states the contiguous rule.

Needles come only from requested paths that are notes (`.md` in any case), using the display name even when that file is missing from the index (`Foo.MD` contributes `Foo`). A non-note such as `pic.png` adds no name needles. It can still be a resolve target, and the note that embeds it is returned. Sources themselves are notes only. Empty requests return `[]`. Duplicates are removed. The result is sorted. ASCII paths match between Rust `BTreeSet` and JavaScript `Array.sort()`.

Fenced and inline code are scanned, as the old search scanned them. `rewriteLinks` still skips that code when it edits, so a fenced mention is returned and then left unchanged. A note whose own body contains its name is included. A short name such as `A` matches widely. Both are the same class of extra candidates the old search produced; the rewrite still changes only real links.

`relocate` order is now: flush editors, keep the old note list, await `linkSources` for every moved note, `renamePath`, move editors, `followMove`, then `fileSettings.renamed` with that source list. A failed read still aborts before any path is renamed. Sources inside the moved folder are mapped forward once with `movedPath` before their editor text is read.

`[[Note\|alias]]` still resolves to `Note` in the index. `rewriteLinks` still does not treat `\|` as an alias separator, so a rename may not rewrite that form. That gap predates this step. This step does not change `rewriteLinks`.

## Bench

No bench. The plan's expected result is a correctness gain (no cap), not a speed gain. A large folder move now scans every note line for every spelling instead of stopping at 20 notes and 500 hits. That cost was not measured.

## Left open

The contiguous-spelling rule is tighter than the old token search. Chris can put the word-split matches back if a line that merely contains each word of a name should still be offered to `rewriteLinks`.

A rename of a folder of very short names still reads every note that contains that substring. The rewrite then no-ops when the text is not a real link. Same practical outcome as the old search, with a different matcher.

The `\|` alias form in `rewriteLinks` is unchanged. A later step can teach the rewriter the same split the index already uses.

Whether `link_sources` stays under the 50ms command bar on a 1,000-note vault was not measured.
